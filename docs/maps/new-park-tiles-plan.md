# Новый парк: дороги и переход на тайлы

## Что работает сейчас

- `src/main/resources/alkosmen/maps/new_park/map-layout.json` содержит черновые осевые линии дорог и железной дороги, ширину дорог в пикселях референса, ID и игровые названия улиц. Это не тайловая карта.
- `NewParkMapLayout` читает JSON. `NewParkWorld` переводит координаты референса в игровые единицы и поворачивает план так, чтобы главная улица шла горизонтально.
- `NewParkGame` рисует траву прямоугольником, а дороги, тротуары и железку полосами через `ShapeRenderer`. Отдельных тайлов земли и дорог в этой сцене пока нет.
- Список препятствий в `NewParkWorld` пуст: герой сталкивается с границей участка, но не с домами, заборами или деревьями.
- `grass_tileset_map.tmx` в `src/main/resources/alkosmen/images/grass_tileset_16x16/` — отдельный пример травяной карты 32x32 клетки, не готовый участок Нового парка.

## Важный вопрос масштаба

Позиция точки из JSON сейчас умножается на `MAP_SCALE = 550 / 12` игровых единиц на пиксель референса. Ширина дороги считается отдельно: `roadWidthUnits = 220 * widthPx / 12`. Так дорогу уже уменьшили относительно расстояний на карте. Размер тайла нельзя выводить из размера пикселя референса или из 16 пикселей существующего травяного атласа.

Перед сборкой карты нужно выбрать один размер клетки в игровых единицах. Например, клетка в 0,5 м означает 50 игровых единиц; визуальный тайл 16x16 при этом просто масштабируется до этой клетки. Все слои, игрок, камера и коллизии должны использовать одну систему мировых координат.

## Как подключать тайлы

1. Начать с небольшого играбельного участка, а не заполнять сразу всю схему района. В Tiled создать отдельный `.tmx` с конечными размерами и слоями земли, дороги, тротуара и декора.
2. Выставить ориентацию и положение участка один раз при создании `.tmx`. Существующий поворот линий JSON учитывать при сверке с референсом; не поворачивать тайлы и игрока разными преобразованиями.
3. Сделать отдельные слои нижнего фона, верхних объектов и объектов коллизий. Рисовать нижние слои, затем персонажа, затем верхние. Препятствия загружать в `CollisionMap` из слоя объектов, а не определять по цвету картинки.
4. Использовать `.tmx` как источник игровой геометрии готового участка. JSON оставить для ID и названий дорог и как референс планировки; после перехода не рисовать поверх тайлов вторую дорогу полосами из JSON.
5. Проверить на экране масштаб героя, ширину проезда, стыки тайлов, проходы, коллизии и камеру. Сборка сама по себе визуальное совпадение не подтверждает.

Не использовать `new_park_zuevka_v1.png` как цельный игровой фон: он показывает один художественный фрагмент и не совпадает с охватом дорожной схемы JSON. Его можно использовать как визуальный ориентир при создании тайлов и декора.
